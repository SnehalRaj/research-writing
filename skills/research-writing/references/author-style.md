# Study how the author presents ideas

Use this procedure when a user asks for prose that follows their research style.
Read complete accepted units before describing that style.
Keep current author instructions distinct from observations about a corpus.

## Establish the evidence

Record the source version, complete unit read and acceptance status.
Choose units that match the target's job: an introduction, a construction or a result discussion.
Read their equations, captions and referenced definitions as part of the explanation.
A short excerpt may illustrate a feature. It cannot establish the unit's overall flow.

Distinguish these kinds of evidence:

| Evidence | What it can establish |
|---|---|
| Current explicit instruction | The requested writing policy. |
| An accepted author passage | An approved way to explain that subject in that unit. |
| A coauthored paper | A pattern in that paper; individual authorship remains uncertain. |
| A reference thesis | A possible structural technique, with its original context. |
| An assistant's style report | A hypothesis to check against the source and current instructions. |

Keep private quotations and annotations private. Public teaching examples require a safe adaptation or publication permission.
Label invented examples as synthetic. Preserve the scientific failure mechanism in the adaptation.

## Describe the explanatory choices

For each complete unit, record what the author makes the reader understand in sequence.
Trace the reader's knowledge after each paragraph.

| Feature | Questions to answer |
|---|---|
| Opening | Which context or problem makes the object necessary? What knowledge does the opening assume? |
| Definitions | Which terms appear first? Does the text state purpose, domain, operation and meaning before use? |
| Construction | Does the reader meet the whole model before its components? What does each component contribute? |
| Equations | Which question motivates each equation? Which symbols need definitions? What consequence follows? |
| Transitions | Does the next sentence add a reason, a consequence, an instance or a restriction? |
| Evidence | Does the result name its comparator, metric, range and assumptions? |
| Ending | Does the unit answer its question and state the next useful question? |

Distinguish repeated author choices from one passage's subject-specific needs.
Return a short profile with locators, examples and limits of inference.
Describe how the explanation works. Avoid claims that a word count or passive rate measures the author's voice.

## Prepare the new research material

Complete the [contribution and definition inventories](templates/03-contributions-and-definitions.md) before a narrative, rewrite or expert critic assignment.
Read the complete agreed source set first. State where the source set ends.
Extract every contribution candidate, including useful negative results, implemented tools and developed study proposals.
Record attribution and evidence status before calling a contribution novel.
Separate prior results, the present work and planned extensions.

Define the basic objects before any contribution relies on them.
Build a dependency order: problem, objects, mechanism, criterion, result, interpretation.
Adjust that order to the actual dependencies. Preserve an accessible supported answer early in the introduction.
An early answer may name a method informally. Its technical explanation must define the necessary objects before use.

Do not force a new article into the source thesis's section titles or page proportions.
Carry across the explanatory choices that fit the article's reader and evidence.

## Structural techniques from the reference notes

These are editorial lenses drawn from reference theses. They are optional techniques, not the named writers' current opinions.

| Lens | Useful technique | Boundary |
|---|---|---|
| Concise chapter opening | Recall the relevant result, identify its restrictive assumption and state the present contribution. | Retain the current author's active voice and complete conditions. |
| Teaching through a construction | Establish the task and objects, then define the model and the quantities the results use. | Avoid detours that postpone the contribution without serving a dependency. |
| Prior work and the research gap | Attribute the prior result, state its assumptions or mechanism, then identify the exact difference or missing element. | Verify the prior result before evaluating its scope. Preserve the condition that makes the comparison fair. |
| Informal and formal results | Give an accurate accessible result with a pointer to its exact statement and proof. | The accessible version must preserve the condition that makes the claim true. |
| Two views of a definition | Pair a formula with a verbal reading or a small worked instance. | Each view should solve a distinct difficulty. Preserve normalisation and domain. |
| Shared background | Define common machinery once and point back when it is reused. | Keep single-use background near its application. Resolve notation conflicts. |
| Comparison table | Compare methods in the same units; define symbols before the table. | Preserve access assumptions and end-to-end costs. |
| Contribution diagram | Show which construction or result supplies another. | Draw an arrow only when there is a real dependency. |
| Discussion | Interpret the supported result, its limits and later relevant work. | Give the conclusion enough substance to answer the original question. |
| Historical motivation | Use a dated, sourced event and a concrete quantity when they explain the research question. | Check primary sources. Keep decorative history out of technical sections. |

Keep publication lists and contributor roles when the document needs attribution across papers.
When merging papers, organise by scientific content and explain the shared question.
Check imports for obsolete references to “the main text”, duplicated background and conflicting symbols.
Visually distinguish a borrowed theorem, a definition and a new result when the format allows it.
Theorem colours, epigraphs, chapter counts and institutional front matter remain local choices.
Check current institutional rules through the appropriate source before treating a precedent as a requirement.

## Produce a usable author profile

Record the following in working notes:

```yaml
author_profile:
  requested_style: "current explicit instructions"
  accepted_units: []  # file, version, complete span, acceptance evidence
  observed_explanation_order: []
  definition_practice: []
  paragraph_connections: []
  result_and_limit_practice: []
  transferable_choices: []  # source locator and why it fits this article
  local_conventions: []
  uncertain_inferences: []
```

Use the profile after the inventories to choose the narrative and paragraph jobs.
Then choose expert critics for the risks the material actually has.
Give critics the profile, evidence map and protected author decisions.
They should report exact passages and reasons, including reasons to keep a passage.
See the [critic briefs](critics/README.md).
