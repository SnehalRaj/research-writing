# Make the rendered document teach the argument

Use rendered pages to check the relationship between the explanation, evidence and layout.
Keep scientific review and visual review as separate outcomes.
The example below is a synthetic teaching example.

## V01. Place each figure with the claim it supports

State the scientific point, then use the figure to explain or support it.
Plan placement and size before building the document.
Inspect the actual rendered page and its neighbours after the build.
Follow explicit author placement requirements when they apply.

**Synthetic example:** A blank page separates a model explanation from two crowded figures.
Changing float settings leaves the reading problem unresolved until the output pages show the explanation and figures in a useful order.
Splitting an authorised composite plot can place each result beside its own discussion.
Check panel coverage, values and attribution after the split.

Use a construction diagram when readers need the mechanism.
Use a result plot when readers need to assess the evidence.
Give panels enough room for labels to remain legible at the intended print size.
Measure figure bounds and caption height when placement is difficult.
A full-page figure needs a reason tied to readability or the argument.

Preserve original result assets and values unless the task authorises a change.
A redraw needs a provenance record and a check against the source.
Seek explicit author agreement before removing, replacing or recomputing a protected main figure.
Access to a local script alone gives no authority to substitute its output.

**Check:** Does the rendered figure support the nearby discussion with readable labels and no avoidable gap?

## V02. Make captions self-contained at the right level

Explain each panel, axis, symbol and colour needed to read the display.
Identify the statistic and scope where these affect interpretation.
Keep implementation detail elsewhere when it obscures the displayed result.
The caption should let readers understand what the figure shows without reconstructing its encoding from distant prose.

Check accuracy before removing a repeated disclaimer.
An unchanged caption can become inaccurate when the plot, model or theorem scope changes.
Check captions during every scientific repair, including text-only repairs that narrow a claim.

**Check:** Can a reader identify the displayed quantity, comparison and essential conditions from the figure and caption?

## V03. Present formal results consistently

Use the document's existing definition, proposition, theorem and proof environments.
Keep its numbering conventions and stable labels.
Define shared concepts once and state contribution-specific extensions explicitly.
Choose a box or display style by its explanatory role and the document's conventions.

Put a short proof immediately after its statement when that placement fits the argument.
For a long appendix proof, keep the main idea and implication in the main text.
End the proof with the established proof marker.

Point cross-references to the exact result that supplies the missing definition or argument.
Check their destinations in the rendered output.
Confirm that the introductory explanation and formal statement describe the same object.

**Check:** Can readers find the assumptions, result and supporting argument from the main account?

## Minimum render check

Record the source revision, build command and PDF identity.
Inspect every changed page and the adjacent pages needed to assess layout.
After a complete rewrite, inspect the full output.
Check float order, large blank areas, clipped labels and broken paragraphs.
Also check table width, orphan lines and chapter boundaries when they can change.
Record required chapter-opening blanks separately from layout faults.

Use one body font size across tables when the document requires a consistent table style.
Adjust columns and spacing to fit before scaling the whole table.
Check label readability at the intended page size.

Test citations, internal links, bookmarks and page labels when their source changes.
Give the author both printed and PDF page numbers when they differ.
Record the reviewed pages and any open layout issue against the exact build.

A clean build records successful compilation.
Visual inspection checks the layout.
Keep scientific verification and author acceptance in their own records.
